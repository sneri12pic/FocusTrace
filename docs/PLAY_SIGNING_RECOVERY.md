# FocusTrace Play-signing update failure and data recovery

## Status

The failure is understood. FocusTrace 1.0.5 was accepted and delivered by
Google Play, but Android rejected it on the affected phone before installation.
The SQLite migration was not involved.

On 19 August 2026, the same-certificate recovery APK was successfully installed
in place on the affected phone as FocusTrace 1.0.6 (`versionCode 7`). Android
still reports the original first-install time, and the app starts without a
Flutter or Android runtime error. The next required step is the manual export in
**Settings → Backup and restore**.

The first 1.0.6 recovery APK repackaged a stale Flutter `app.so`: its Android
version and native document bridge were new, but its Dart Settings UI was from
the previous build. This made the Backup and restore card appear to be missing.
Running `flutter clean`, fetching packages again, and rebuilding regenerated
`app.so` with the new UI. The clean APK was installed in place, and the phone's
UI hierarchy now confirms that **Backup and restore**, **Export data**, and
**Import data** are present.

Do not uninstall the affected FocusTrace installation until a portable backup
has been exported and checked.

## Confirmed error

On 19 August 2026, the affected phone reported:

- Package: `com.stepandemianenko.focustrace`
- Installed version: `1.0.2` (`versionCode 3`)
- Installer: none
- Initiating package: `com.android.shell`
- First and last install time: 28 July 2026 at 20:58:46

Google Play then attempted to install `versionCode 6`. Package Manager rejected
each attempt with result `-7` and this message:

```text
Existing package com.stepandemianenko.focustrace signatures do not match newer version
```

The installed APK and the locally signed release AAB have this certificate:

```text
SHA-256: 9A:F6:80:86:EE:F4:44:39:97:43:CB:79:92:74:6F:D0:
         DA:81:5D:59:8F:24:18:59:54:A6:87:4B:C0:BD:75:C5
```

This proves that a local recovery APK signed by the existing release keystore
can update the affected installation without clearing its private data.

## Root cause

The phone contained a locally installed production-package APK. It was
installed through ADB, even though the Google Play testing page was later used.

Google Play App Signing uses two identities:

1. The upload key signs the AAB submitted to Play.
2. Google's app-signing key signs the APK delivered to users.

The local APK uses the upload certificate. The APK generated by Google Play
uses Google's app-signing certificate. Android permits an in-place update only
when the package name and signing identity are compatible, so the Play update
cannot replace this local installation.

The application ID did not change. The new AAB's version code is higher. The
testing track worked, proven by Play delivering version code 6 to Package
Manager. This is therefore not a track, versioning, Room, or AAB-content issue.

## Why the SQLite change is unrelated

FocusTrace 1.0.5 changes the local schema from version 3 to version 4 and adds
`usage_intervals` and `restriction_events`. SQLite opens and migrates only after
Android has installed and launched the APK. The observed rejection happens
during package verification, before application code or SQLite can run.

The migration is also covered by tests that preserve existing version-3 usage
rows while adding the new tables.

## Implemented fix

FocusTrace 1.0.6 adds **Settings → Backup and restore**:

- **Export data** writes a versioned JSON backup through Android's system file
  picker.
- **Import data** validates the FocusTrace format and merges all records in one
  SQLite transaction.
- Import never clears the destination database.
- Matching primary keys use the imported values, making repeated import safe.
- The format contains usage sessions, settings, daily usage, usage intervals,
  and restriction events.
- Android refuses backup files larger than 10 MB before passing them to Dart.

The JSON file is intentionally portable and readable. Treat it as private: it
contains app names, package names, usage times, restrictions, and settings.

## Recovery procedure for the affected phone

### 1. Build the recovery APK

From the repository root:

```powershell
flutter clean
flutter pub get
flutter build apk --release
```

The APK is created at:

```text
build/app/outputs/flutter-apk/app-release.apk
```

Confirm its SHA-256 certificate matches the fingerprint above:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.0\apksigner.bat" `
  verify --print-certs build/app/outputs/flutter-apk/app-release.apk
```

If an installed APK does not show newly added Flutter UI, compare the timestamp
of `build/app/intermediates/flutter/release/arm64-v8a/app.so` with the source
files and search the binary for a known new label. A stale timestamp indicates
that a clean rebuild is required.

### 2. Install it without clearing data (completed on the affected phone)

```powershell
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

`-r` requests an in-place replacement. Stop if Android reports a certificate
mismatch. Do not add `-d`, do not uninstall first, and do not use `pm clear`.

For the affected phone this command returned `Success`; version `1.0.6 (7)` is
now installed and the original first-install timestamp remains unchanged.

### 3. Export and verify (manual step still required)

1. Open FocusTrace.
2. Open **Settings → Backup and restore**.
3. Press **Export data**.
4. Save the JSON file to Downloads, Google Drive, or another location outside
   FocusTrace's private app storage.
5. Open or copy the file and confirm it contains:
   - `"format": "focustrace-portable-backup"`
   - `"formatVersion": 1`
   - a `tables` object
   - the expected historical rows

Keep a second copy on a computer or cloud drive before proceeding.

### 4. Publish the Play build

Build the AAB from the same 1.0.6 source:

```powershell
flutter build appbundle --release
```

Upload `build/app/outputs/bundle/release/app-release.aab` to the intended Google
Play testing track. Verify Play Console shows `1.0.6 (7)` and that the release
is active for the tester account.

### 5. Switch signing identities

Only after the backup is verified:

1. Uninstall the locally signed FocusTrace installation.
2. Install FocusTrace 1.0.6 from the Google Play testing page.
3. Open **Settings → Backup and restore → Import data**.
4. Select the exported JSON file and confirm the import.
5. Check dashboard history, reports, exclusions, and restrictions.
6. Re-grant Usage Access, overlay, and notification permissions if Android asks.

An uninstall is unavoidable because Android cannot change directly between the
two unrelated signing identities. The portable backup is what preserves the
data across that uninstall.

## Diagnostic commands

Show installed version and installer identity:

```powershell
adb shell dumpsys package com.stepandemianenko.focustrace
adb shell cmd package list packages -i | findstr focustrace
```

Capture a failed Play attempt:

```powershell
adb logcat -c
# Press Update in Google Play, then run:
adb logcat -d | findstr /i "focustrace signature UPDATE_INCOMPATIBLE INSTALL_FAILED"
```

The characteristic failure is `signatures do not match newer version` or
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`.

## Prevention

- Use `flutter run` for development. Debug builds use
  `com.stepandemianenko.focustrace.dev` and cannot replace the Play app.
- Never install a locally built release APK with the production application ID
  on a phone intended to receive Google Play updates.
- Use Play internal/closed testing for production-package testing.
- Keep Export/Import available in future releases.
- Before any destructive recovery, create and verify a portable backup.
